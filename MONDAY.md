# MONDAY — what moves to the GPU cluster / HPCC

Everything below is launched from a clone of this repo with the same venv
(`pip install -r requirements.txt`).  Results land in `results/<e>/results.json`
and are merged into the page with `python scripts/make_figures.py`.

| Job | Command | Resources | Expected |
|---|---|---|---|
| E1 full | `python experiments/e1_gpt2_noise.py --device cuda --steps 400 --batch 8 --block 512` | 1 GPU (>= 16 GB), ~2-3 h, downloads GPT-2 124M + WikiText-2 | perplexity vs sigma for pretrained-at-noise, noise-aware fine-tuned, clean read |
| E1 with write noise | `python experiments/e1_gpt2_noise.py --device cuda --c2c 0.02` | same | sensitivity of fine-tuning to pulse noise |
| E8 full size | `python experiments/e8_nanogpt_tiles.py --d 384 --layers 6 --heads 6 --steps 5000 --ft-steps 1000 --seeds 3 --threads 16` | CPU node (tiles are CPU torch) or `--device cuda` after moving the tile ops to GPU | the 10.6M-parameter version of E8 |
| E3 50 seeds | `python experiments/e3_drift.py --full --procs 32` | CPU node, 32 cores, ~4 h | fitted sigma* with tight bootstrap CI, both homeostasis arms |
| E3 N = 512 | `python experiments/e3_drift.py --N 512 --seeds 20 --procs 32` | CPU node, ~8 h | does Delta U shrink with N (Burak-Fiete 1/N diffusion) |
| E7 10 seeds | `python experiments/e7_modularity.py --full --procs 10` | CPU node, 10 cores, ~2 h | Q, MI, compositional gap with error bars; also `--rule np` for the node-perturbation arm |
| E5 self-organisation at 32x32 | `python experiments/e5_grid_selforg.py --sheets 32x32 --seeds 3 --points 800 --points-h2 350 --procs 3` | CPU node, ~6 h | only meaningful if the programmed reference certified on Saturday |
| E9 longer stream | `python experiments/e9_trainability.py --seg 5000 --threads 16` | CPU node | recovery times with less noise |
| E10 10 seeds | `python experiments/e10_continual.py --full --threads 8` | CPU node, ~1 h | consolidation result with error bars |

Notes
* `--device cuda` is implemented for E1 and E2 only; the torch tile layer
  runs on CPU tensors (it would run on GPU unchanged but has not been tested
  there).
* Launch long CPU jobs under `systemd-run --user` or `sbatch`; the scripts
  print progress with `flush=True` only inside training loops, so redirect to
  a log and read it with `grep -v Warning`.
* The page (`results/index.html`) is regenerated by
  `python scripts/make_results_page.py` once the JSON files are back.
